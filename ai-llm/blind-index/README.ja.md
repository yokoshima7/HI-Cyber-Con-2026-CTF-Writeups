# Blind Index — 後続インスタンスで過去の参照文字列を採点する

[English](README.en.md)

分類: AI / LLM · チーム: ReFlection（Agentic AI）· [問題ページ](https://ctf.hiddeninvestigations.net/challenges?challenge=9a82a5dd-903a-4000-bb12-5856c046e9ba)

24文字の16進参照文字列が10件与えられ、類似度スコアの照会サービスを使う問題。同じインスタンスで自分の参照文字列を直接照会すると `reference_record` として拒否される。公開APIは `/records`、`/status`、`/lookup` で、1インスタンスにつき400件を採点できる。突破口は、インスタンスを作り直すと拒否対象の10件は変わる一方、採点関数は維持されていたことだった。

## 解法

1. 最初の自チームインスタンスで10件の文字列と0始まりの番号を保存する。近傍文字列399件の採点によるローカル推定では、近い3組の順序を確定できなかった。
2. 後続の自チームインスタンスを起動すると、`/records` は別の10件を返した。既知の非参照文字列2件を再採点した結果は過去の値と小数6桁まで一致し、この範囲では採点関数が安定していることが分かった。
3. 最初のインスタンスの参照文字列10件を、後続インスタンスの `/lookup` へ一括送信する。今度は拒否対象から外れており、正確なスコアが返る。

   | 旧番号 | スコア | 旧番号 | スコア |
   | ---: | ---: | ---: | ---: |
   | 0 | +0.224797 | 5 | +0.067722 |
   | 1 | +0.080045 | 6 | +0.118937 |
   | 2 | +0.519453 | 7 | +0.370114 |
   | 3 | −0.129120 | 8 | −0.077011 |
   | 4 | +0.170042 | 9 | −0.270360 |

4. 降順に並べると `2,7,0,4,6,1,5,8,3,9`。区切りなしで連結した `2704615839` をフラグ形式に入れたところ、公式問題画面は `Flag correct!` と `Challenge solved!` を表示し、チームの解答数が59/69になった。終了時の公式公開記録にもBlind Indexが含まれる。

Flag: `hiCTF{2704615839}`

この順序は保存した最初の参照集合について確認済みである。別の参照集合は異なる順序だったため、普遍的な固定順序とは言えない。新しいインスタンスが別の集合を生成した後でも、停止済みの古い集合の順序がなぜ受理されたかはプラットフォームからは分からない。公開APIにも答えの記法は書かれていなかった。AIを使った近似モデルの検討より、インスタンスをまたぐ対照実験と正確な採点が決め手になった。
