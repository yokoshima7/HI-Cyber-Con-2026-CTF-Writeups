# Epsilon Drift（Reverse Engineering）

[English](README.en.md)

[公式問題](https://ctf.hiddeninvestigations.net/challenges?challenge=61fa3c15-3a28-4a4e-903d-678d58706c88) · 配布ZIPのSHA-256: `993a5ed3ced717af48dedf7b18fd54396ba55e314ea4519613a96a9c6b05284f`

チェッカーは64ビット値4個をIEEE-754の倍精度浮動小数点として扱う。仮数と指数の検査で最初の2個は `1.1` と `2.2` に定まり、3個目は両者を加算した**実際のbinary64値**になる。十進近似値を置くのではなく、浮動小数点演算後のビット列を取得する必要がある。

4個目が罠である。浮動小数点比較では `+0.0` と `-0.0` は等しい。しかし後の符号ビット検査は `-0.0`、すなわち `0x8000000000000000` でのみ成功側へ進む。4個の値をリトルエンディアンの32バイトとして連結し、そのSHA-256からカウンター付きSHA-256の鍵ストリームを作る。最初の42バイトをELF内の暗号文とXORする。

結果は `hiCTF{1eee754_s1gn3d_z3r0_1u1p_dr1ft_eps!}`。復号文のSHA-256はチェッカーに埋め込まれた期待値と一致し、大会終了時の公式解答済み一覧にもEpsilon Driftがある。正のゼロでは符号ビットの条件を満たさない。
